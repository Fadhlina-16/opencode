# External FE Handoff Pack (Strict)

## Purpose
Use this template when outsourcing page implementation to external frontend developers without giving repository access.

This contract is strict:
1. Follow design tokens as closely as possible.
2. Flag all differences explicitly.
3. Keep deliverables easy to review.
4. Keep integration back to Vue/Inertia straightforward.
5. Preserve Cornell UIUX handoff contract sections for direct review and merge planning.
6. Respect `layout_policy` in `handoff-manifest.json`.

---

## Required Deliverables (all required)

Default mode is `vue-first`.

### Vue-first deliverables (stage-specific)

Stage 1 (UIUX Designer):
```text
<page-name>-handoff/
  page.vue
  edge-case-matrix.md
  assets/        # optional, only if required
```

Stage 2 (QA):
```text
<page-name>-handoff/
  external-fe-review-checklist.md   # completed
  qa-findings.md                     # severity + rework notes
  edge-case-matrix.md                # state validation status updated
  assets/        # optional, only if required
```

Stage 3 (Software Dev):
```text
<page-name>-handoff/
  page.vue
  token-diff.md
  integration-map.md
  edge-case-matrix.md
  assets/        # optional, only if required
```

### Legacy HTML deliverables (compatibility mode only)

```text
<page-name>-handoff/
  review.html
  token-diff.md
  integration-map.md
  assets/        # optional, only if required
```

If any required file is missing for the selected mode, handoff is rejected.

Team sync-back requirement:
1. Stage PIC may edit files required for that stage.
2. Stage PIC must submit all updated artifacts together and notify the team that sync-back is ready.
3. Next stage cannot start until sync-back package is received.
4. Next stage must use the latest stage pack version plus previous stage outputs.
5. Full-flow default: coordinator sends one `<page>-cornell-workflow-<YYYYMMDD-HHmmss>.zip` pack; each stage returns a stage-labeled artifact zip (`...artifact-stage1.zip`, `...artifact-stage2.zip`, `...artifact-stage3.zip`).

## Package Ownership (important)

There are two different packages in this process.

### A) Outbound reference pack (you send to external)

```text
<page-name>-handoff-reference/
  handoff-manifest.json
  cornell-preview.css
  reusable-shell/              # optional visual review references (when layout_policy=reusable-shell)
  token-class-reference-pack.md
  external-fe-handoff-pack.md
  edge-case-matrix.md          # stage-dependent
  external-fe-review-checklist.md  # stage-dependent
  README.md                    # stage-dependent
  assets/        # optional
```

Notes:
1. `cornell-preview.css` is generated by your team from the real app build.
2. External uses this pack as styling reference.
3. External should not modify and re-author your CSS.
4. `handoff-manifest.json` defines mode, stage, AI read allowlist/denylist, and expected outputs.
5. If `layout_policy=reusable-shell`, `reusable-shell/` files are visual review references and should not be re-authored unless explicitly requested.

### B) Inbound handoff pack (external sends back)

Notes:
1. This is the package you review and integrate.
2. In `vue-first` mode, `page.vue` is the primary artifact.
3. In `legacy-html` mode, `review.html` remains the primary visual artifact.

## Source Inputs

Provide these inputs to FE:
1. Figma frame(s) or image export(s)
2. This handoff template
3. Approved token/class reference pack (shared externally)
4. Target page name and route intent
5. Required viewport(s) for review (default desktop + mobile)
6. Visual reference URL: `https://elearning.cornell.eacanta.org/design-system`
7. `handoff-manifest.json` from outbound package

Reference rule:
1. FE must cross-check visuals and primitives against `https://elearning.cornell.eacanta.org/design-system`.
2. If observed implementation differs from the visual reference, record it in `token-diff.md` as `diff`.
3. FE should read only files in `ai_read_allowlist` and avoid files in `ai_read_denylist`.

## File Rules

### 1) `page.vue` (default in `vue-first`)
Purpose: direct conversion-ready output for integration.

Must include:
1. Clear section wrappers with stable IDs (for example `id="hero"`, `id="filters"`, `id="table"`).
2. Vue 3 `<script setup>` format.
3. States shown where relevant (default, hover, active, disabled, error).
4. Desktop and mobile behavior in one component.
5. Content-only implementation by default (no sidebar/topbar shell) unless handoff instructions explicitly override this.

Constraints:
1. No inline style unless documented in `token-diff.md`.
2. No raw hex unless documented in `token-diff.md`.

### 2) `review.html` (only for `legacy-html`)
Purpose: compatibility visual artifact for older handoff flow.

Rules:
1. Keep same stable section IDs used for eventual Vue conversion.
2. Content-only layout (do not recreate app shell).

### 3) `edge-case-matrix.md`
Purpose: track required states across Stage 1 -> Stage 3.

Rules:
1. Keep required state rows updated (`todo`/`done`/`deferred`).
2. Every `deferred` row must have a reason.

### 4) `token-diff.md`
Purpose: force explicit drift reporting.

Use this table format:

| Section | Figma Element | Figma Value | Intended Token/Class | Implemented Class | Status (`match`/`diff`) | Severity (`P0`-`P3` for `diff`) | Reason |
|---|---|---|---|---|---|---|---|
| hero | title | 32/700 | `text-3xl font-bold text-heading` | `text-3xl font-bold text-heading` | match | n/a | n/a |

Rules:
1. Every `diff` row must include a reason.
2. Every `diff` row must include severity (`P0-P3`).
3. If no differences exist, still submit file with `No token differences.` summary.

### 5) `integration-map.md`
Purpose: reduce merge effort into this repo.

Required sections at top of file:

```markdown
## Cornell UIUX Frontend Handoff

### Implementation Notes and Invariants
- ...

### Required Tokens and Primitives
- ...

### QA Acceptance Checklist
- [ ] ...
- [ ] ...

### Non-Goals and Boundaries
- ...
```

Use this table format:

| Review Section ID | Block Summary | Vue Conversion Hint | Target Repo Path | Integration Notes |
|---|---|---|---|---|
| hero | top banner and CTA | hero/header block with same section ID | `resources/js/Pages/<PageName>.vue` | content-only; no shell duplication |

Rules:
1. Map every major section.
2. Highlight any block that should become shared component(s).
3. Do not assume exact internal component names if repo access is not provided; describe behavior and visual intent instead.
4. Note shell dependency clearly (shared `AppLayout` handles sidebar/topbar).
5. If `layout_policy=reusable-shell`, reference provided shell files for review context and call out any integration assumptions.

### 6) `assets/` (optional)
Include only assets needed to render page parity.

Rules:
1. Keep filenames stable and descriptive.
2. Include source note (`from figma export`, `provided by client`, etc.).

## Acceptance Gates Before Submission

External FE must self-check:
1. Primary output (`page.vue` in vue-first or `review.html` in legacy-html) is visually aligned to references.
2. All token differences are documented in `token-diff.md`.
3. Section IDs are clear and stable for Vue conversion.
4. Deliverables open without file errors.
5. `integration-map.md` includes Cornell UIUX handoff sections (invariants, token/primitives, QA checklist, boundaries).
6. `edge-case-matrix.md` is updated when present in the selected stage pack.
